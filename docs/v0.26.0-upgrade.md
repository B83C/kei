# v0.26.0 upgrade and compatibility

This release adds automatic recovery for eligible historical paths and selected sparse targets, bounded URL-variant retention and normal-run storage diagnostics. It preserves unsupported identity and checkpoint holds. See the [changelog](../CHANGELOG.md#0260---2026-10-22).

## Upgrade

1. Stop all kei workers, schedulers and automatic updaters that share the state or media directories.
2. Preserve a verified matched cold backup of configuration, state and media/sidecars, including SQLite WAL/SHM/journal companions and any history files. Retain the old binary or immutable image digest.
3. Upgrade one worker using the same account, realm, directories, selection and metadata options. Opening owned state, including through status, can upgrade schema 35 to 36 and consolidate qualifying retained response duplicates. For v0.24.x or earlier, follow the [account-ownership adoption procedure](v0.25-upgrade.md#back-up-and-adopt-existing-state) first.
4. Run normal sync. Review its completion or held-work summary and any unexpected file or state-write errors. Preserve state between runs; eligible completed work should be reusable after reopening. Unresolved work is not permission to clear state or reset checkpoints.

No special diagnostic image or debug flag is needed for the new storage summaries. If a problem occurs, retain the normal run output and use [support export](support-export.md); inspect exported material before sharing it. A successful download count alone does not establish backup completeness.

## Evidence retention and capacity

Qualifying versioned asset responses that differ only in validated download URLs share retained evidence. The current incoming response remains available to the normal consumer. Compaction preserves historical provenance, identity and recovery obligations but discards superseded retrieval URLs and the ability to reconstruct every redundant original response body.

Unknown fields, missing version or descriptor bindings, different source scope and other meaningful differences remain separate. Unsupported provenance dependencies remain raw. Logical budget reclaim is not physical file shrinkage; genuinely distinct evidence can still reach the configured capacity. A capacity refusal must not be bypassed by deleting evidence.

## Rollback

Older binaries cannot open schema 36. Stop all writers and preserve the post-upgrade set before restoring the complete matched pre-upgrade configuration/state, SQLite companions and media/sidecars with the old binary or image. Do not lower the schema number, mix SQLite companions or restore only the database.

## Remaining holds

Unknown ownership, ambiguous identities, incomplete source coverage and genuine metadata obligations remain held while eligible work can progress. Local Trusted Legacy File acceptance is not provider proof. RUNNING indexing and bounded selections retain their existing checkpoint restrictions. Existing duplicates and previously damaged media are not repaired automatically.

Keep existing metadata-write choices unchanged during upgrade. The [metadata guidance](metadata.md) describes supported writes and preservation limits.
